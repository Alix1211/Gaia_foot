# GAIA SLIME FUTSAL | AI 공동 작업 규칙

## 1. 세션 시작 절차 (매번 필수)

1. `README.md` → `docs/GAME_BIBLE.md` → **`docs/CHARACTERS.md`** → `docs/DECISIONS.md` → `docs/WORKLOG.md`를 먼저 정독한다. 대사·AI 행동·스탯·상황 이벤트 작업 시 반드시 7인 페르소나 기준과 대조한다.
2. 현재 GitHub `main`의 브랜치/커밋 SHA, 가장 최근 테스트 파일, 마지막 성공한 작업 범위를 확인한다.
3. 문서와 실제 코드가 다르면 **사용자의 최신 확정 결정**을 우선한다. 기존 코드를 자동으로 고치지 말고 충돌을 보고한다.
4. 지금 요청이 **검토/기획/코드/에셋/테스트/배포** 중 무엇인지 구분한다. 검토만 요청했다면 절대 구현으로 넘어가지 않는다.

## 2. 작업 전 보고·승인

- 요청 범위, 바꿀 파일, 기존 기능에 영향을 줄 가능성, 사용자가 테스트할 부분을 **짧게 설명**한다.
- **승인되지 않은 새 기획·대사·신체 이미지·HUD·컷신·메뉴·성장 시스템 추가 금지.**
- '이것도 넣어 드렸습니다'라는 선의의 확장은 하지 않는다.
- **캐릭터 일관성:** 같은 상황에도 7인 각자의 성격·말투·동기·반응이 달라야 한다. 이름만 바꾼 공통 대사 금지. 성장 후에도 기본 페르소나 유지.
- 명시적 수정 요청이 들어온 항목은 그 범위에서만 수정한다.
- 불가능하거나 제한이 있는 요청은 구체적 해당 요청에 대해서만 설명하고, 창작자의 의도·취향을 평가하지 않는다.

## 3. 수정 시 기술 규칙

- **기본형 유지:** `baseline/SLIME_FUTSAL_v052.html`을 직접 수정하지 않는다.
- **작동하는 기능 보존:** 골, 패스, 슛, 대시, 조작, 교체, AI, 골키퍼, 충돌, 공 물리 보존을 우선한다.
- **시스템 독립:** 오피스의 반복 애니메이션은 연출 참고, 웰니스/핑퐁의 성장식은 별개.
- **팀 규칙 일관성:** 주인공/상대가 공유하는 자원·스킬·장비·경기 규칙을 따로 하드코딩하지 않는다. 단, 사용자가 승인한 캐릭터별 차이와 이벤트 룰은 예외.
- **UI 절제:** 설명·도움말 남발 금지. 새 버튼/스포일러 UI는 실제 기능이 열릴 때만 표시하는 방향을 검토한다.
- **에셋 보호:** 얼굴 외 인간 신체 그림을 임의로 채택하지 않는다. 기존 그림의 화풍·크기·용도 임의 변경 금지.
- **저장 보호:** 영속 세이브가 도입되면 반드시 호환성/백업/복원 전략을 먼저 검토한다.

## 4. GitHub 기록 규칙

매 수정 건마다 다음을 남긴다.

```text
날짜/시간(KST):
요청 요약:
승인 범위:
작업 대상 브랜치 / 기준 SHA:
변경된 파일:
게임플레이 영향:
검증: [정적 코드 검사] [자동화 테스트] [브라우저 실행] [Android 실기기]
검증하지 못한 부분:
커밋 SHA / 브랜치 / 실행 URL:
문서 변경: GAME_BIBLE / DECISIONS / WORKLOG
다음 할 일 / 보류:
```

- 커밋 전에 현재 브랜치/이전 기준과 diff를 확인한다.
- **테스트용 브랜치와 안정 버전을 구분**한다. 사용자 요청 없이 `main`을 시험용으로 덮지 않는다.
- 업로드 후에는 원격 커밋 SHA와 파일 접근을 확인한다. 확인 못 했으면 '업로드 완료'라고 말하지 않는다.
- **GitHub 저장소 주소가 제공되기 전에는 푸시했다고 주장하지 않는다.**
